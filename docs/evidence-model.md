# Evidence model

Evidence entries identify the API surface, operation, accepted scope alternatives, introduction/deprecation metadata, verification version, source URL, evidence type, and confidence. The bundled registry is offline and verified against Shopify API `2026-10`. Shopify's official [version schedule](https://shopify.dev/docs/api/usage/versioning), checked on 14 October 2026, lists `2026-10` as latest stable and `2027-01` as the release candidate. API-version status uses the documented `accessibleUntil` deadline where one is known; `2025-10` remains stable until 16 October 2026 at 15:00 UTC. The `--api-version` option and report metadata identify that status and whether the evidence pack applies. Selecting a release candidate does not apply stable-version mappings: Admin operations remain UNKNOWN until evidence is verified. Versions outside the status snapshot are labelled unverified rather than unsupported.

The 2026-10 additions include statically identifiable GraphQL fields for billing fees, payment-instrument email, market hierarchy, analytics, reports, ShopifyQL, and root or discount-nested rollout connections. Resource-specific access needed by protected rollout payloads is intentionally not inferred.

The analyzer also maps the topic-level scopes printed on Shopify's 2026-10 Events topic references for the 18 bundled topics. It does this only when the app configuration sets `[events].api_version = "2026-10"`. Shopify announced Next Gen Events as generally available in 2026-10; the versioning page's note that Events remains unstable is stale relative to the [release announcement](https://shopify.dev/changelog/blog/next-generation-events-are-now-generally-available) and [subscription reference](https://shopify.dev/docs/apps/build/events/subscribe). Unknown topics and other Events versions remain UNKNOWN. This mapping does not infer trigger-specific scope requirements, or scopes used by a subscription's custom GraphQL `query`; query and `query_filter` contents are not reported.
